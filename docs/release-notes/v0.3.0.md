# Bootwitch v0.3.0

## Release summary

Bootwitch v0.3.0 gives projects a predictable user-owned home. The new
`bootwitch setup` command prepares a minimal workspace under `$HOME/Bootwitch`,
and new projects now default to `$HOME/Bootwitch/Projects` regardless of the
caller's current working directory.

## Highlights

- Run `bootwitch setup` once to create `Projects/` and `Documents/` beneath the
  current user's `$HOME/Bootwitch` workspace.
- Run `bootwitch init NAME` from any directory to create
  `$HOME/Bootwitch/Projects/NAME`.
- Preview workspace or project creation with `--dry-run`.
- Use `setup --workspace PATH` for a one-time alternative workspace target and
  `init --root PATH` for a one-project destination override.
- Keep existing repositories unchanged: setup does not clone, move, rename, or
  adopt project content.
- Use `bootwitch new-script` as a CLI front door to a generated shell project's
  own annotated script template and documentation refresh.
- Preview a formula update locally without changing the tracked formula; the
  GitHub verification workflow performs the same read-only check.

## Safety and compatibility

- Setup is idempotent for regular directories and refuses an empty, unset, or
  non-absolute `HOME` when deriving defaults. It also refuses empty workspace
  overrides, existing files, and symbolic links at its selected directory paths.
- Project creation continues to validate names, refuse existing destinations,
  stage complete projects beside their destination, and publish with a native
  exclusive rename.
- `BOOTWITCH_HOME` still identifies the installed toolkit; it is distinct from
  the user workspace at `$HOME/Bootwitch`.
- Bash 3.2+, Python 3, macOS, and Linux remain supported. Git is required for
  default project initialization unless `--no-git` is supplied.

## Upgrade notes

The default project root changed from `$HOME/Developer/Projects` to
`$HOME/Bootwitch/Projects`. Existing projects are not moved. Continue using
`--root` when an established project location should remain the destination.

After installing or upgrading:

```sh
bootwitch setup --dry-run
bootwitch setup
bootwitch doctor
```

See the [workspace guide](../workspace-guide.md) for the complete model and
existing-project boundaries.

## Validation

- Run `make setup` to install the pinned, checksum-verified local ShellCheck.
- Run `make check` for syntax, integration, filesystem, publication, generated
  documentation, and tool-setup coverage.
- After the `v0.3.0` tag exists, validate the release artifact with:

  ```sh
  bash tools/bump-brew-formula.sh --dry-run v0.3.0
  ```

## Distribution

The canonical public source is
[`naomijnguyen/Bootwitch-CLI`](https://github.com/naomijnguyen/Bootwitch-CLI).
After the release tag is verified, update the reviewable formula in this
repository and mirror the same formula to the public
[`naomijnguyen/homebrew-bootwitch`](https://github.com/naomijnguyen/homebrew-bootwitch)
tap. The GitHub formula workflow is deliberately manual and read-only: it
validates the tagged archive and checksum but never commits, pushes, or edits a
release.
