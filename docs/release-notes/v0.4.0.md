# Bootwitch v0.4.0

This release makes Bootwitch's generated projects easier to inspect and extend while adding bounded tools for media preparation and public-export review. It does not automatically publish projects or modify existing generated projects.

## Highlights

- `bootwitch project-info [--project PATH]` prints one validated project metadata snapshot without running project code.
- `bootwitch new-script NAME --language python` delegates to a generated shell project's own Python starter when that project supports it. Bash remains the default. The starter teaches imports, functions, loops, and command-line options using only Python's standard library.
- Generated shell projects include a module catalog for lookup without executing modules during discovery.
- Media optimization writes an optional derivative to a new output path. Review images visually and videos by playback before using them on a site.
- GitHub-safe export tools validate an explicit allowlist, stage a private copy, and verify its exact file tree. A passing stage is **not** permission to publish: selected content, build artifacts, and the destination repository still need separate review and approval.
- Failed, marked export runs older than 14 days can be previewed for cleanup; removal requires an explicit apply action.

## Compatibility and limits

- Existing generated projects keep their own versioned templates. The toolkit CLI forwards `--language python`, but a project created before this starter was added will reject that option until deliberately migrated.
- The top-level toolkit needs Python 3 for project creation. Generated shell workflows do not gain a Python runtime requirement unless you opt into a Python script.
- The public-export tools assume trusted local parent directories and do not provide a hostile-filesystem race-proof boundary. Do not treat staged output as a safe public repository without independent review.
- The media optimizer is a local pilot, not a sandbox for attacker-controlled files.

## Release validation

The source tree passed `make check` on macOS and Linux CI. A clean archive-shaped local install created a shell project, inspected its metadata, generated and ran the Python word-count script through the toolkit CLI, and passed the generated project's tests.

The Homebrew formula is updated separately after the tag exists, using the hosted archive's SHA-256. The formula's test creates a disposable project rather than checking only `help`.
